# 4. 만들기

# 5. 저장 — Supabase

## 프롬프트 ② 표를 만드는 SQL

```text
방명록 글을 Supabase 에 저장하려고 해. SQL Editor 에 붙여 넣을 SQL 을 supabase.sql 파일로 만들어 줘.
- 표 이름 guestbook: id, name, message, created_at
- name 은 20자, message 는 200자 이내
- RLS 를 켜고, 누구나 읽기 · 쓰기만 가능 (수정 · 삭제는 불가)
- 브라우저용 공개 키(anon)로 쓸 수 있게 필요한 grant 도 포함
- 각 줄에 한국어 주석
```

* 만든 supabase.sql 을 전부 복사 → Supabase **SQL Editor → New query** → 붙여 넣기 → **Run** → **Table Editor** 에서 guestbook 확인

## 어려우면 — SQL 실행을 ego 에 맡기기

* 먼저 ego 창에서 Supabase 에 로그인해 둔다

```text
ego-browser skill 을 먼저 실행해 사용법을 읽고, ego 로 Supabase 의 archives-homepage 프로젝트 SQL Editor 를 열어 supabase.sql 을 실행해 줘.
- 로그인 · 비밀번호 입력 · 경고 창 승인이 필요하면 멈추고 나에게 물어
- 끝나면 Table Editor 에서 guestbook 표가 보이는지 확인해 알려 줘
```

## 프롬프트 ③ 화면과 연결

```text
site/index.html 의 방명록을 Supabase 의 guestbook 표와 연결해 줘.
- 주소와 공개 키는 site/config.js 에 따로 두고, 내가 붙여 넣을 자리를 비워 둬
- supabase-js 는 CDN 으로 불러와 줘 (설치 없이)
- «남기기»를 누르면 저장하고, 최신 20개를 새 글이 위로 오게 보여 줘
- 실패하면 이유를 화면에 한국어로 보여 줘
```

* Supabase **Project Settings → API Keys** 에서 Project URL 과 **publishable 키**(sb_publishable_…)를 복사해 site/config.js 빈자리에 붙여 넣고 저장(Ctrl + S)
* 직접 붙여 넣기 어려우면 아래처럼 시켜도 됨 — **publishable 키만**

```text
이 주소와 키를 site/config.js 에 넣어 줘.
주소: (Project URL 붙여 넣기)
키: (sb_publishable_ 로 시작하는 키 붙여 넣기)
```

## 어려우면 — 두 값 옮기기도 ego 에 맡기기

```text
ego 로 Supabase 의 archives-homepage 프로젝트 Project Settings → API Keys 를 열어 Project URL 과 publishable 키(sb_publishable_ 로 시작)를 읽어 site/config.js 에 넣어 줘.
- secret 키(sb_secret_)는 읽지도 쓰지도 마
- 넣은 뒤 config.js 내용을 보여 줘
```

* 보여 준 config.js 의 키가 `sb_publishable_` 로 시작하는지 눈으로 확인

# 6. 공개 — Cloudflare

* Cloudflare 대시보드 → **Workers & Pages** → **Create** → Pages 쪽 → **Upload assets**(직접 올리기) → 프로젝트 이름 → **site 폴더**를 끌어 놓기 → **Deploy**
* 메뉴 이름은 바뀔 수 있음 — «Pages» · «Upload» 가 들어간 버튼을 찾음
* 고친 뒤에는 같은 프로젝트에서 **Create new deployment** 로 다시 올림

# 부록 A — GitHub 연동

* ⚠ 직접 올리기로 만든 Pages 프로젝트는 Git 연동으로 바꿀 수 없음 — Git 연동용 프로젝트를 새로 만들고 주소가 바뀜
* ego 에서 GitHub → **New repository** → 이름 archives-homepage → **Private** → Create

```text
이 폴더를 git 저장소로 만들고, GitHub 의 archives-homepage 저장소에 올려 줘.
- 저장소 주소: https://github.com/<내 아이디>/archives-homepage
- git 이 설치돼 있지 않으면 설치 방법부터 알려 줘
- 비밀번호 · secret 키가 든 파일은 올리지 마
```

* Cloudflare → Workers & Pages → Create → Pages → **Connect to Git** → 저장소 선택
    - Framework preset **None** · Build command **비움** · Build output directory **site** → **Save and Deploy**
* 이후 수정은 이렇게:

```text
제목 색을 바꾸고 커밋 · 푸시해 줘
```

# 부록 B — Google 로그인

1. **Google Cloud 콘솔**(console.cloud.google.com) → 새 프로젝트
2. **Google Auth Platform** → 시작하기 — 대상 «외부», 테스트 사용자에 내 메일
3. **Clients → Create client** → 유형 «웹 애플리케이션»
    - 승인된 JavaScript 원본: `https://내주소.pages.dev`
    - 승인된 리디렉션 URI: `https://<ref>.supabase.co/auth/v1/callback` (`<ref>` = Project URL 앞부분)
4. Client ID · Client Secret 복사
5. Supabase **Authentication → Sign In / Providers** → Google 켜기 → Client ID · Client Secret 붙여 넣기 → Save
6. Supabase **Authentication → URL Configuration** → Site URL · Redirect URLs 에 pages.dev 주소

```text
방명록에 Google 로그인을 붙여 줘.
- 위쪽에 «Google 로 로그인» · «로그아웃» 버튼
- 로그인한 사람만 글을 쓸 수 있고, 이름은 Google 계정 이름으로 자동 입력
- guestbook 표에 작성자 계정(user_id) 칸을 더하고, 본인 계정으로만 쓰게 하는 RLS 정책을 supabase.sql 에 추가
- 로그인 뒤 돌아올 주소는 지금 열린 페이지 주소로
```

* 새 SQL 실행 → 다시 올리기 → **pages.dev 주소에서** 확인 (내 PC 파일로는 로그인 확인이 안 됨)
* 🔴 Client Secret 은 Supabase 에만 — 홈페이지 · GitHub · 채팅 금지

## PROMPT.md 전문

아래를 작업 폴더에 **PROMPT.md** 로 저장한다.

```markdown
# 목표
가상의 «한빛기록관» 소개 + 방명록 홈페이지를 만들어 인터넷 주소로 공개한다.

# 재료
- 화면: site/index.html, site/config.js — 설치가 필요 없는 HTML · CSS · JavaScript
- 저장: Supabase 프로젝트 archives-homepage (이미 만들어 둠, Seoul) · 표 guestbook
- 공개: Cloudflare Pages 프로젝트 archives-homepage
- 브라우저: ego — 브라우저 작업 전에 `ego-browser skill` 을 실행해 사용법을 읽는다

# 순서
1. site/ 에 홈페이지를 만든다 — 기관 소개 카드 3장 + 방명록(이름 · 한 줄 · 최신 20개)
2. supabase.sql 을 만든다 — guestbook 표, RLS 켜기, 누구나 읽기 · 쓰기만, anon grant
3. ego 로 Supabase SQL Editor 를 열어 supabase.sql 을 실행하고 Table Editor 에서 확인한다
4. ego 로 Project Settings → API Keys 에서 Project URL · publishable 키를 읽어 site/config.js 에 넣는다
5. `npx wrangler pages deploy site --project-name archives-homepage` 로 배포한다
6. ego 로 배포 주소를 열어 방명록에 «자동 테스트» 글을 남기고, 새로고침 뒤에도 보이는지 확인한다

# 지킬 것
- secret 키 · DB 비밀번호 · Client Secret 은 파일과 채팅에 쓰지 않는다
- 가입 · 로그인 · 결제 · 비밀번호 입력 · 무언가를 지우는 일이 필요하면 멈추고 나에게 묻는다
- 단계가 끝날 때마다 한 줄로 보고한다

# 끝난 기준
배포 주소에서 방명록 글이 저장 · 표시되면 완료. 그 주소를 알려 준다.
```
