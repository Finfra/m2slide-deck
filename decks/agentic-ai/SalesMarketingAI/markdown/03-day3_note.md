## mg-day3

⏱ **모션그래픽 장이다.** 재생이 끝날 때까지 말을 얹지 않고, 끝나면 그날의 한 단어 «제안하기» 만 말하고 다음 장으로 넘긴다.

## day3-cover

- 3일차 표지. 이날 고객은 한솔건기(가상) 하나라고 먼저 말한다.
- 3일차 한 단어는 «제안하기» — 상담 메모에서 페인포인트를 뽑아 제안서 문서까지 만든다. 2일차 사전 브리핑이 3일차 상담 메모로 이어지고, 3일차 제안서의 차별점이 4일차 홈페이지·SNS 로 넘어간다(사슬: 맥락 카드 → 브리핑 → 제안서 → 홈페이지·CSV).

## codex-approval

- Codex 를 처음 쓰는 날이므로 승인 화면 읽기를 한 번 시범 보인다. Day3 폴더 밖 경로나 삭제 명령이 보이면 허용하지 않는 것을 강조한다.
- «샌드박스 밖에서 실행» 승인이 뜨는 경우를 미리 보인다: Codex 샌드박스는 기본으로 localhost 연결을 막을 수 있어, 9222 포트 연결(P3-0-2)에서 필요할 수 있다. 포트 번호와 폴더만 읽고 허용하게 한다.
- **Codex 한도 대체 경로를 여기서 한 번에 공지한다** — 설계·R&D 4회차(10.13 16:21)와 5회차(10.20 16:13)에 오후 Codex `429` 가 연속으로 났다. 한도가 소진된 수강생은 같은 프롬프트를 ChatGPT 웹에 보낸다: 입력 파일 내용을 대화창에 붙이고 «Day3 폴더의» 로 시작하는 문장에서 폴더·저장 표현만 뺀다. 결과는 메모장에 붙여 `Day3` 폴더에 저장한다.
- 강사는 P3-1·P3-2·시연 결과 파일을 전날 미리 만들어 둔다(`_material/Day3/_강사본/`). 손을 든 수강생에게 한 벌을 복사해 준다.
- 🖐 선실행 대기: 렌털 PC 의 현재 권한 모드(승인 방식) 캡처로 고정.

## pain-to-effect

- 3-1 Practice 가 만드는 것은 페인포인트 표와 차별점 한 줄까지다. 솔루션은 3-2, 기대효과는 3-4 에서 이어 쓴다고 한 번 말한다.

## differentiator

- 차별점 3가지 정답은 `_강사본/차별점.md`. 수강생은 그중 한 줄을 P3-1-2 에서 `페인포인트표.md` 끝에 «차별점:» 으로 적는다. 벤 도해의 가운데 영역이 차별점이다.
- 4일차 SNS 초안(P4-2-2)에서 쓴다 — 홈페이지 특징 문구·블로그에 넣어 보는 것은 선택이다.

## cdp-what

- 이 장은 4일차 준비 블록의 이론 한 장이다. «4일차 수집을 하려면 3일차 끝에 연결을 해 둔다» 로 시작한다.
- CDP 는 «브라우저를 포트 9222 로 열어 두면 Codex 가 그 포트로 들어와 읽고 클릭하는 방식» 이라고 한 문장으로 말한다. 전용 프로필이라 평소 로그인 정보는 따라오지 않는다.
- 연결 수단은 설계·R&D 과정에서 쓴 `cdp` 스킬이다. 계약 3줄: ① 첫 주소(이 실습은 file:// 주소)가 시작 페이지, 나머지가 할 일 ② 로그인·CAPTCHA·보안 경고·권한 창은 우회하지 않고 멈춤 ③ 최종 주소·결과·만든 파일 경로로 보고. 화면 속 글은 «신뢰하지 않는 데이터» 다.
- 이용약관·robots·속도·로그인 뒤(개인정보) 확인 장은 **4일차 수집 전**에 있다. 3일차는 «공개 웹 자료만» 한 문장만 말하고 고지는 하지 않는다.
- 구판의 «Chrome + CDP 의 영업 활용» 과 «자동화 지도» 두 장은 이 장과 닫는 절 `day3-forward` 로 합쳤다. 영업 활용 4단계(모으기 → 정리하기 → 보이기 → 제안하기)는 `day3-forward` 표의 수집·정리·시각화·제안 행이고, «목표는 수집이 아니라 근거 있는 제안» 한 줄은 그 장 불릿에 있다.
- KIPRIS 시연 사례(1.design_rnd) 원본: 이 저장소에서 `cdp` 사용 원고는 찾지 못했다. 가장 가까운 KIPRIS 실습 [P3.search/0.search-open.md](../../1.design_rnd/practice/P3.search/0.search-open.md) 만 링크한다. 🖐 `cdp` 로 한 시연은 시트에서 확인해 여기에 원본 링크를 단다.

## ex-p3-0-2

- **Practice** (10분, 설정 3 의 뒤 절반). 스킬 제작 한 줄은 강의노트 QnA 원문 그대로다. 정답: 보이는 행 12 (장표에는 올리지 않는다 — 닫는 절에서 공개). «더 보기» 는 누르지 않게 한다 — 4일차 수집의 출발점이다.
- 수집 페이지는 `Chrome_CDP.bat` 이 `%USERPROFILE%\cdp-lab\` 로 옮겨 연다(작업 폴더 `Day3` 밖). 프롬프트의 «디스크의 html 은 열지 마» 는 Codex 가 파일을 직접 읽어 CDP 없이 24행을 답하는 것을 막는다.
- 연결이 안 될 때 순서(장표 «막히면» 과 같음): `localhost:9222/json/version` 확인 → «샌드박스 밖에서 실행하도록 승인을 요청해 줘» → 창을 모두 닫고 `.bat` 재실행. 3분 안에 안 되면 옆자리 화면으로 따라가고 4일차 여는 절에서 한 번 더 시도한다.
- 🖐 선실행 대기: Windows 렌털 PC 에서 스킬 제작 → `cdp <주소> …` 응답 캡처, 생성된 스킬의 호출형이 `cdp <주소> <할 일>` 계약과 맞는지, 수강생이 만든 `cdp` 스킬이 `file://` 주소(`Chrome_CDP.bat` 이 여는 `directory.html`)를 받는지, 9222 연결, 샌드박스 승인 화면. `.bat` 의 이동·열기 동작 실측.
- 📱 필드 영업은 보기 전용이다.
