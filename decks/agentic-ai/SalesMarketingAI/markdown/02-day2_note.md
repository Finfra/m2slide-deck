## vscode-what

* 영업·마케팅 수강생은 VSCode 를 처음 보는 사람이 많다. «개발자 도구» 라는 말에 겁먹지 않게 «코딩은 하지 않는다» 를 먼저 말한다. 화면 4구역은 실제 VSCode 창을 띄워 손으로 가리킨다. 터미널은 3일차부터 Codex 가 쓰는 자리라 «보기만 한다» 고 말한다.
* 쓰는 이유는 둘이다 — 마크다운 문서를 쓰고 미리 보는 자리, Codex 를 담는 그릇. 1일차 ChatGPT 는 답이 대화창에 남았고, VSCode 에서는 결과가 내 PC 폴더의 파일로 남는다는 대비를 한 번 말한다.
* 1분 안에 끝낸다. 영역 이름을 외우게 하지 않는다 — 다음 Practice 에서 손으로 찾는다.
* 마지막 불릿(쓰는 기능은 확장과 터미널 둘)은 «VSCode 에 있는 나머지 기능은 몰라도 된다» 는 안심 한 줄이다. 디버깅·Git·확장 마켓 전체를 설명하지 않는다 — 영업 수강생이 쓰지 않는 기능을 장으로 세우면 배우지 않을 것에 시간을 쓴다(설계·R&D 1-0 «VSCode 주요 기능 5종» 은 의도적으로 한 줄로만 흡수, Issue64 단계2 A05).

## markdown-what

* 정의와 HTML 대비를 먼저 말한다 — HTML 은 태그로 감싸 사람이 읽기 어렵고, 마크다운은 줄 앞에 기호만 붙여 그대로 읽힌다. 존 그루버(2004)와 깃허브 `README.md` 는 말로 한 줄만 한다.
* 영업 수강생에게는 «ChatGPT 답을 복사하면 기호가 따라온다» 가 가장 와닿는 이유다. 한계(도구마다 모양이 다름·두 단 배치 불가)도 같이 말해 기대를 맞춘다.
* 개요 4장(이 장 + 문법 ① ② ③)은 구판 구성(Issue44 «부록1. MarkDown»)의 복원이다. 시간이 모자라면 문법 ① ② 는 표를 읽기만 하고, ③ 은 P2-0-2 코드 블록으로 대신한다.

## markdown-syntax-1

* 표 6줄을 위에서부터 읽는다. 오른쪽 «미리보기에서 보이는 모양» 은 강사 화면에서 같은 줄을 실제로 입력하고 `Ctrl+Shift+V` 로 보여 주면 가장 빠르다.
* 기호 뒤 한 칸 띄우기를 일부러 한 번 틀려 보인다(`#제목` → 제목이 되지 않음). 목록 아래 빈 줄을 빼먹으면 표가 깨진다는 것도 여기서 한 번 보여야 P2-0-2 에서 덜 막힌다.
* 그림 — VSCode 에서 왼쪽에 # · - · ** 기호가 보이는 소스, 오른쪽에 제목·목록·굵게·인용·구분선으로 바뀐 미리보기(vscode.dev 에서 촬영 · 2026.10.25)

## markdown-syntax-2

* 링크·이미지는 대괄호 다음에 소괄호 — 이미지는 느낌표가 하나 더 붙는다는 것만 짚는다. 이 과정에서 이미지 삽입은 직접 하지 않는다.
* 코드 블록은 «교안의 프롬프트 상자와 같은 것» 이라고 말한다. 상자 안 글이 기호 그대로 보이는 이유가 이것이며, 프롬프트를 복사할 때 상자의 복사 버튼을 쓰게 되는 근거다.

## markdown-table-syntax

* 위쪽 주석은 구분선 줄 `| :-- | :-- | --: |` 만 떼어 세로선·왼쪽 정렬·오른쪽 정렬을 짚는다. 아래 코드 블록의 표 3줄과 같은 줄이다.
* 이 장이 P2-1-2(비교표.md 저장)의 사전 지식이다. 세로선 한 줄이 한 행이고 둘째 줄이 머리글 구분선이라는 것, `:--` 와 `--:` 의 정렬 차이만 말한다.
* 🔴 «화면의 표를 끌어 복사하면 이 형식이 되지 않는다» 가 실패 원인 1순위다. ChatGPT 의 코드 블록 복사 버튼으로 받아야 한다. 예제 표의 값(GGB·DU·250·140)은 요약표 값과 같은 예시이며 정답이 아니다(정답은 MBI 350 환산).
